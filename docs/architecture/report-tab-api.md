# 리포트 탭 주간 민심 급지 계약

관련 이슈: [#190](https://github.com/sugkamoney/geupjido-backend/issues/190). 화면 기준은 디자이너 PC 핸드오프의 `11-report.md`다.

이 문서는 **레일의 공개 주간 리포트**에 적용한다. 월드컵에서 일정 판 수를 채운 뒤 보는 개인별 `내 선택 리포트`는 별도 기능이다. 디자이너 시안은 화면 구성과 탐색 동작의 기준이며, 표 수와 급지 전환 조건은 아래의 합의된 서비스 정책을 따른다. 시안에 적힌 숫자는 실제 응답값이 아니다.

## 발행 시점과 보존

- 한 기간은 한국 시간 **일요일 18:00 이상부터 다음 일요일 18:00 미만**이다. 매주 일요일 **18시 집계로 리포트를 미리 완성하고 21시에 공개**한다. `publishedAt`은 실제 공개 시각이며 21:00 이전일 수 없다.
- 급지와 권역별 상태는 기존 3시간 급지 계산식으로 **선택 시각이 마감 전인 표만** 다시 계산한 결과다. 이는 21시의 현재 급지 발행 결과와 독립적이다. 18~21시의 표는 다음 리포트 기간에 포함된다.
- 마감 계산·초안 저장이 실패하거나 완료되지 않았으면 오래된 값으로 새 리포트를 만들지 않는다. 이후 예약 실행에서 같은 18시 마감값을 재계산하고, 성공한 초안을 21시 이후 공개한다. 장애 시 정확히 21시에 공개되지 않을 수 있다. 같은 기간을 다시 처리해도 리포트 한 편만 남는다.
- 마감 전 유효표로 민심 급지를 계산할 수 있는 권역이 없으면 첫 리포트 전 상태다. 조건을 충족한 첫 일요일 18시 기준으로 첫 리포트를 준비하고 21시에 공개한다. 이후 발행한 리포트의 내용은 뒤따르는 투표·급지 발행으로 바뀌지 않는다.
- 리포트는 `periodStart`, `periodEnd`, `publishedAt`과 해당 마감 집계의 식별 시각을 구분해 보존한다. 목록 탐색에서 최신·이전·다음 여부는 저장된 리포트 순서로 결정한다.

## 저장 구조

[V30 마이그레이션](../../src/main/resources/db/migration/V30__create_weekly_report_snapshot.sql)은 기간별 `weekly_report` 한 행과 권역별 `weekly_report_zone_snapshot`을 만든다. `period_end_at`의 고유 제약은 같은 주의 초안·발행본 중복을 막는다. 마감 계산이 성공하면 한 트랜잭션에서 기간·마감 계산 완료 시각과 모든 권역의 이름, 지역, 민심 급지, 세 전환 수치를 초안으로 보존한다. DB 제약은 `published_at`을 21시 이후로 제한하며, 이 값이 채워진 행만 공개 조회 대상이다.

권역 스냅샷은 이후 권역·구 이름이나 급지가 바뀌어도 리포트가 변하지 않도록 현재 마스터에 외래 키를 걸지 않는다. 권역과 구 ID는 현재 지도 화면으로 이동할 때 사용하므로, 과거 ID가 현재 서비스에서 사라졌다면 화면은 해당 상세의 404를 처리해야 한다. `VOTE` 권역만 `vote_tier`를 보존하며, 아직 모으는 중인 `INITIAL` 권역의 초기 급지를 민심 급지로 저장하지 않는다. DB 트리거는 발행 이후 리포트 행과 권역 스냅샷의 추가·수정·삭제를 막는다.

기간의 참여자·유효표 수, 비교 가능한 급지 변경 수, 요약 문장은 공개 전에 초안에 채운다. 계산은 18시 마감 이전의 유효한 선택과 보존된 이전·현재 스냅샷에 한정한다. 18시 이후의 투표나 21시 급지 발행 결과를 이번 스냅샷에 섞지 않는다.

투표 저장소는 `forEachRecordedVoteBefore(cutoff)`로 `selected_at < cutoff`만 읽고, 기존 유효표 판별 규칙에 전달한다. `WorldcupVoteRatingService.calculateBefore(cutoff)`는 이 경로를 통해 기존 급지 계산식을 재사용한다. 따라서 마감 정각에 기록된 표는 다음 기간에 속한다. `WeeklyReportPeriod.latestClosedAt(now)`은 한국 시간의 최근 일요일 18시 마감과 21시 공개 가능 시각을 계산한다. 예약 작업은 한국 시간 매 10분마다 이미 준비된 초안의 공개를 먼저 확인하고, 누락된 초안을 준비한 뒤 공개 가능 여부를 다시 확인한다. 개발·운영 프로필에서는 `WEEKLY_REPORT_SCHEDULE_ENABLED`로 켜고 끌 수 있고, 로컬 프로필에서는 기본으로 꺼져 있다. 개발·운영의 예약 작업 스레드 2개는 21시 급지 갱신이 준비된 리포트의 공개를 지연시키지 않도록 한다. JVM 중단·DB 장애·긴 잠금 대기 시에는 정각 공개가 지연될 수 있다.

초안 준비가 예외로 실패하면 별도 트랜잭션에서 `weekly_report_attempt_failure`에 해당 마감의 실패 시각을 기록한다. 첫 발행 전에도 이 기록이 있으면 조회 상태가 `COLLECTING` 대신 `PREPARING` 또는 `DELAYED`가 된다. 재시도에서 초안 저장에 성공하면 실패 기록은 삭제한다. DB 자체가 응답하지 않는 동안에는 실패 기록도 저장할 수 없으므로 운영 로그를 확인해야 한다.

3시간 급지 발행과 주간 집계가 같은 분에 시작하면 PostgreSQL `REPEATABLE READ`에서 발행 잠금 행의 동시 갱신 때문에 `CannotAcquireLockException`이 발생할 수 있다. 예약 작업은 이 충돌을 **새 트랜잭션에서 한 번 즉시 재시도**하고, 다시 실패한 경우에만 실패 시각을 기록한다. 이후 예약 실행에서 마감 집계가 정상 완료됐지만 민심 급지 조건을 충족한 권역이 없다면 실패 기록을 지우고 첫 발행 전 `COLLECTING` 상태로 돌아간다. 발행 가능한 권역이 있으면 초안을 저장하면서 실패 기록을 지운다. 이때 실제 사용자 표나 발행본을 임의로 만들지 않는다.

## 주간 숫자와 비교

| 화면 값 | 데이터 기준 |
|---|---|
| 참여한 사람 | 해당 기간의 **유효표**를 낸 서로 다른 익명 방문자 수. 한 사람이 여러 표를 내도 한 명으로 센다. |
| 모인 표 | 해당 기간에 선택돼 마감 집계에서 유효한 표 수. 건너뛰기는 포함하지 않는다. |
| 급지 바뀐 곳 | 직전 리포트와 비교해 **1~5급지 구간**이 바뀐 공통 민심 권역 수. 소수 첫째 자리만 바뀌고 구간이 같으면 세지 않는다. |

상승·하락 목록은 직전 리포트와 현재 리포트에 모두 민심 급지가 있는 권역을 비교한다. 급지 숫자가 **작아지면 상승**, 커지면 하락이며 차이가 큰 순으로 각각 최대 5곳을 제공한다. 같은 숫자면 목록에서 제외한다. 첫 리포트에는 직전 리포트가 없으므로 변화 개수와 비교 문장을 `null` 또는 비교 불가 상태로, 상승·하락 목록은 빈 목록으로 제공한다. 이를 `0곳 변화`와 혼동하지 않는다.

`급지 경계에 가까운 권역`은 현재 민심 급지에서 바로 위 구간의 마지막 값까지 차이가 작은 순으로 최대 5곳이다. 예를 들어 현재 2.0이면 1급지의 1.9까지 0.1이 남았다. 이미 1급지인 권역은 제외한다. 이는 현재 수치의 거리이며 다음 집계에서 실제로 상승한다는 예측은 아니다.

`표를 모으는 중`은 아직 `VOTE`로 전환되지 않은 권역 가운데 유효표가 1표 이상인 최대 5곳이다. 각 행에는 해당 권역의 유효표·서로 다른 방문자·권역 간 유효표와 세 전환 조건을 제공한다. 전환은 **50표·10명·권역 간 20표를 모두 충족**해야 하므로 시안의 `n / 80표` 막대 하나로 완료 여부를 판단하지 않는다. 첫 리포트가 공개되기 전에는 상세 조회가 없으며, 현재 투표 진행 상태는 지도 탭 상태 API를 사용한다.

`구별로 보면`은 두 리포트에 **모두** 민심 급지가 있는 같은 권역 집합으로 각 구의 이전·현재 평균을 계산한다. 새로 투표 급지로 전환된 권역의 편입만으로 구 평균이 변한 것처럼 표시하지 않는다. 평균 차이의 절댓값이 큰 구 최대 5곳을 제공하고, 비교 대상 권역 수를 함께 제공한다.

요약 문장은 저장된 리포트의 실제 비교 결과에서 확인 가능한 사실만 사용한다. 첫 리포트에는 `지난 리포트와 비교하면`이라는 표현을 쓰지 않는다. 변화가 없거나 특정 구역에 표시할 대상이 없으면 빈 목록과 그에 맞는 상태를 반환하고 시안용 행을 만들지 않는다.

요약의 주간 상승·하락 분포는 직전과 이번 리포트에 모두 민심 급지가 있는 권역의 **급지 수치 변화 상위 각 5곳**에서 계산한다. `3~5급지`, `1~2급지` 묶음은 변화 **이전** 급지로 분류한다. 양쪽 목록이 각각 3곳 이상이고 상승 상위 목록의 과반이 3~5급지, 하락 상위 목록의 과반이 1~2급지일 때만 `중간 급지가 올라오고 위쪽 급지가 내려오는 흐름`이라고 쓴다. 그 외에는 상승·하락 권역 수를 사실대로 말한다. 두 목록 모두 비면 변화가 없다고 안내한다.

같은 사실을 매주 같은 어투로 반복하지 않도록 조건별 문장 틀을 3개씩 둔다. 마감 주차로 문장 틀을 결정해 초안에 저장하므로 같은 리포트를 다시 조회해도 문장은 바뀌지 않는다. 문장 틀은 수치와 방향을 바꾸지 않으며 조건에 맞지 않는 추세 표현을 쓰지 않는다.

시안의 `배치표와 가장 다르게 본 곳`은 서비스 DB가 원본 배치표의 출처를 구분하지 않으므로 **저장된 초기 급지와 이번 민심 급지의 차이**로 표현한다. V31부터 권역 스냅샷에 `initial_tier`를 함께 보존하고, 민심 급지 권역 중 절댓값 차이가 최대인 권역과 `높음/낮음` 방향을 요약에 넣는다. 같은 최대 차이와 방향을 가진 권역은 이름 최대 2개와 `등`으로 표현한다. 초기 급지가 없거나 차이가 0인 권역만 있으면 이 문장을 생략한다. 요약은 초안 작성 시 한 번 계산해 저장하므로 발행 후 현재 마스터 값이 바뀌어도 달라지지 않는다.

## 조회 API와 화면 연결

`GET /api/v1/reports`는 공개된 리포트만 최신순으로 반환한다. 각 행에는 `reportId`, `periodStart`, `periodEnd`, `publishedAt`, `latest`가 있다. `state`는 첫 발행 전 `COLLECTING`, 현재 마감 초안의 21시 대기 또는 이전 발행본 이후 새 마감 준비 중에는 `PREPARING`, 공개 시각이 지나도 이번 주 발행본이 없으면 `DELAYED`, 최신 마감 발행본이 있으면 `PUBLISHED`다. `expectedReleaseAt`은 공개 예정 또는 지연 중인 시각을 알려준다. 아직 발행본이 없으면 `collectingZones`에 **마지막 3시간 급지 집계**에서 확인된 수집 중 권역 최대 5곳을 표 많은 순으로 제공한다. 이 값은 실시간 표 수가 아니며 집계가 한 번도 발행되지 않았다면 빈 목록이다. 발행본이 있으면 목록의 `collectingZones`는 비우고 선택한 주의 상세 스냅샷을 사용한다.

`GET /api/v1/reports/{reportId}`는 발행본의 주간 참여자·유효표·변경 권역 수와 요약, 상승·하락·경계 근접·수집 중·구별 변화 목록, `previousReportId`·`nextReportId`를 제공한다. 첫 리포트의 `changedGradeZoneCount`는 `null`이고 비교 목록은 빈 배열이다. 초안·없는 번호는 `REPORT_NOT_FOUND` 404이며, 두 조회 응답 모두 `Cache-Control: no-store`다. 권역 행을 누른 뒤 지도 상세는 기존 `GET /api/v1/map/zones/{zoneId}`를 사용하고, 구 행은 기존 `GET /api/v1/map/cities`의 `bounds`로 확대한다. `[비교하러 가기]`는 기존 월드컵 시작 흐름으로 연결한다.

로컬 PostgreSQL·PostGIS 복제 DB에서 가상 투표를 4주 누적해 두 API와 발행 스냅샷을 검증하는 절차 및 결과는 [한 달치 주간 리포트 검증](../../scripts/test/weekly-report-month-smoke.md)에 기록한다. 이 검증은 발행 시각과 마감 경계를 주입식 `Clock`으로 재현한다.

리포트 API는 Swagger의 **리포트** 그룹에 랭킹 다음으로 놓는다. 개인별 선택 기록과 공개 주간 집계 결과를 같은 응답이나 이름으로 섞지 않는다.
