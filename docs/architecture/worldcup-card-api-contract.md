# 아파트 월드컵 카드 정보·API 응답 계약

- 상태: **카드 표시 항목 확정** — 실제 조회 API 구현 전
- 작성일: 2026-11-02
- 관련 이슈: [#113](https://github.com/sugkamoney/geupjido-backend/issues/113), [투표 정책 #109](https://github.com/sugkamoney/geupjido-backend/issues/109)

## 목적과 확정된 범위

한 판에 두 아파트 단지 중 하나를 반드시 선택한다. 게임당 10판이며, 배너 진입과 권역 선택 진입 모두 같은 카드 정보를 사용한다. 게임 생성·일일 한도·선택 저장은 이 문서의 응답 초안 범위가 아니다. 기존 결정은 [후보 활성 기준](../history/2026-11-02-voting-candidate-activation.md)과 [투표 정책 #109](https://github.com/sugkamoney/geupjido-backend/issues/109)에 있다.

## 현재 백엔드에서 확인한 데이터 의미

| 값 | 확인된 의미 | 카드 표기 시 주의 |
|---|---|---|
| `complex.id`, `name` | 단지 식별자와 K-apt 기반 단지명 | 같은 이름의 단지를 구분할 위치 정보가 필요하다. ID는 화면 문구가 아닌 선택 요청의 식별자다. |
| `zone.city.name`, `zone.name`, `zone.tier` | 단지가 배정된 시·구, 권역 이름, 현재 급지 | 카드 상단에 세 값을 함께 표시한다. 급지 값이 바뀌면 다음 조회부터 바뀐 값을 사용한다. |
| `households` | 단지의 세대 수 | 초기 활성 후보는 300세대 이상이다. |
| `approval_date` | 사용승인일 | 화면에는 `사용승인 연도`로 표기한다. |
| `price`, `representative_area`, `last_deal_date` | **선택된 실제 매매 거래 한 건**의 만원 단위 가격, 실제 전용면적(㎡), 계약일 | 대표 면적에 가까운 거래를 우선 선택하므로 모든 면적의 거래 중 가장 최근 계약이라고 단정할 수 없다. 세 값을 함께 제공한다. |
| `score`, `zone_rank` | 평가 점수·잠정 순위 | 이번 카드에는 표시하지 않는다. |

근거: [단지 도메인](../../src/main/java/com/geupjido/complex/domain/Complex.java), [권역 도메인](../../src/main/java/com/geupjido/zone/domain/Zone.java), [대표 거래 산정 기록](../history/2026-10-28-complex-representative-price.md). 현재 활성 조건은 권역·좌표·사용승인일·300세대 이상·일반 아파트 매매 대표 거래를 요구한다.

## 카드 표시 항목

| 위치 | 표시 내용 |
|---|---|
| 카드 상단 | 시·구명, 권역명, 현재 급지 |
| 제목 | 단지명 |
| 기본 정보 | 사용승인 연도, 세대 수, 선택된 거래의 실제 전용면적 |
| 거래 정보 | `최근 거래`와 선택된 거래의 매매가격 |

화면 구성은 2026-10-08 데스크톱 HTML 시안의 투표 카드를 따른다. 예시 순서는 `용산구 / 서빙고 / 1.9 / 서빙고 신동아 2차 / 1985년 · 1,750세대 · 83㎡ / 최근 거래 1.80억`이다. 이 숫자와 단지명은 시안의 데모 값이며 실제 응답값으로 대체한다. 서버는 가격을 만원 단위 정수, 면적을 실제 ㎡ 값, 계약일을 날짜로 전달하고 클라이언트가 화면 문구로 변환한다.

시안의 `최근 거래`는 현재 저장된 대표 매매 거래의 가격을 보여주는 화면 문구다. 주간 수집·재계산은 이 값을 갱신하지만, 선택 규칙이 면적을 우선하므로 단지의 모든 평형을 통틀어 가장 최근 계약이라는 뜻은 아니다. API에는 계약일을 함께 포함해 가격의 기준 시점을 확인할 수 있게 한다.

가까운 역과 단지 한 줄 설명은 이번 카드에서 제외한다. 역 데이터는 현재 없고, 한 줄 설명은 실제 데이터의 비교 기준을 정한 뒤 다룬다. 사진, 상세 주소, 단지 점수와 권역 내 순위도 이번 카드에는 표시하지 않는다.

## 응답 객체 제안

아래는 한 카드의 데이터 형태 제안이며, 엔드포인트 경로·게임/대진 응답 구조를 확정한 것은 아니다. API는 JPA 엔티티를 직접 반환하지 않고 별도 DTO로 만든다.

| 필드 | 타입·단위 | 사용 |
|---|---|---|
| `complexId` | 문자열 | 선택 요청에서 단지를 식별하는 값. 화면 문구에는 사용하지 않음 |
| `name` | 문자열 | 단지명 |
| `cityName` | 문자열 | 시·구명 |
| `zoneName` | 문자열 | 권역명 |
| `zoneTier` | 소수, 급지 | 현재 권역 급지. 카드 상단에 표시 |
| `households` | 정수, 세대 | 세대 수 |
| `approvalYear` | 정수, 연도 | 사용승인 연도 |
| `representativeSale.exclusiveAreaSquareMeters` | 소수, ㎡ | 선택된 매매 거래의 실제 전용면적 |
| `representativeSale.priceTenThousandWon` | 정수, 만원 | 같은 거래의 가격 |
| `representativeSale.contractDate` | `YYYY-MM-DD` | 같은 거래의 계약일 |

`representativeSale`은 현재 활성 후보가 일반 아파트 매매 대표 거래를 가진다는 조건을 전제로 한다. 이 조건을 바꾸면 응답의 필수 여부와 가격 출처 표시도 다시 정해야 한다.

권역 선택 시 활성 후보가 0개라면 게임을 시작하지 않고 투표 가능한 인접 권역을 보여주기로 결정했다. 이를 위한 별도 조회 응답에는 우선 `zoneId`, `cityName`, `zoneName`, `activeComplexCount`를 제안한다. 사용자가 인접 권역을 고른 뒤 게임이 시작되므로, 단순 조회에서는 일일 게임 수를 차감하지 않는다. 실제 API 경로와 인접 권역 미리보기 범위는 후속 구현 이슈에서 정한다.

## 후속 구현 범위

이번 문서는 카드 표시값과 한 카드의 응답 필드를 정한다. 실제 API 경로, 게임 대진 응답, 역 데이터와 한 줄 설명은 후속 구현 작업에서 다룬다. HTML 시안의 투표 진행 방식은 [투표 정책 #109](https://github.com/sugkamoney/geupjido-backend/issues/109)의 최신 결정에 맞춰 구현한다.
