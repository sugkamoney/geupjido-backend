# 공동주택 단지 초기 적재 재개와 실패 기록

## 실행 방식

2026-10-26 로컬 PostgreSQL을 대상으로 권역 매핑의 법정동 254개를 작은 묶음으로 수동 적재했다. `scripts/complex/import_complexes.py`가 기존 Spring 적재 작업을 호출하고 법정동별 결과를 `data/complex/import-runs/local.jsonl`에 누적한다. 매니페스트는 인증 정보를 포함하지 않으며 Git에서 제외한다. 성공 또는 빈 목록으로 확인된 법정동은 재실행 시 건너뛰고, 부분 실패·목록 실패는 다시 시도한다. 이번에 사용한 API 요청 시작 간격은 300ms다.

매핑 순서 15~49번 중 30개 법정동을 실행 기록에 남겼다. 이 중 20개는 `SUCCESS`, 1개는 `EMPTY`, 9개는 재시도 대상이다. 앞서 수집한 매핑 순서 0~14번의 완료 여부는 이 매니페스트에 포함되지 않으므로, 이 수치를 전체 254개의 완료율로 해석하지 않는다.

## 로컬 DB 확인 결과

- 단지 465건, 법정동 32개에 데이터가 있다. 이 중 현재 권역 매핑 대상은 단지 464건·법정동 31개이고, 매핑 밖 기존 데이터는 1건이다.
- 300세대 이상 단지는 216건이다.

- 같은 법정동을 다시 실행했을 때 기존 단지는 건너뛰었고 중복 저장은 관측되지 않았다.

### 추가 재시도

사용자 요청으로 `1171010100`, `4113511500`, `1165010900`을 한 곳씩 다시 실행했다. 세 곳 모두 목록 API `04`로 실패했고, 연속 실패 기준에 도달해 추가 호출을 중단했다. 매니페스트의 최신 상태는 `SUCCESS` 20곳, `EMPTY` 1곳, `PARTIAL` 1곳, `LIST_FAILED` 8곳이다. 로컬 DB는 이전과 같은 단지 465건·법정동 32개다. 세 곳에서 기존에 저장된 부분 적재 데이터는 유지됐다.

### 원인 조사와 이후 상태

- 공공데이터포털의 [목록 API 안내](https://www.data.go.kr/data/15057332/openapi.do)는 `04`를 허용되지 않은 HTTP 요청 또는 제공기관 API 응답 처리 실패로 설명한다. `22`는 일일 한도 초과, `23`은 초당 한도 초과로 별도 표기한다.
- 로컬 설정은 HTTPS `apis.data.go.kr/1613000/AptListService4`를 사용한다. `GET /getLegaldongAptList4`에 `serviceKey`, `pageNo=1`, `numOfRows=100`, `bjdCode`를 보낸다. 인증키 값은 조사 로그와 문서에 기록하지 않았다.
- 같은 키·URL·법정동 코드 `1171010100`의 직접 요청이 처음에는 HTTP 200의 JSON 오류 본문에서 `04`를 반환했으나, 잠시 뒤 `00`을 반환했다. 다른 실패 코드 `4113511500`, `1165010900`, `1121510400`도 직접 조회에서 `00`이었다. 같은 코드의 Java 적재도 다시 성공해 기존 4건을 건너뛰고 누락 9건을 저장했다.
- 같은 코드의 직접 요청은 2초 간격 8회와 300ms 간격 8회 모두 `00`이었다. 이번 표본에서는 짧은 요청 간격이 `04`를 재현하지 않았다. 고정된 URL·파라미터·인증키 오류와 확정적인 한도 소진을 뒷받침하는 증거는 없다. 다만 `04`가 발생한 내부 위치와 조건은 외부 응답만으로 특정할 수 없다.
- 조사 후 로컬 DB는 전체 단지 474건·법정동 32개, 권역 매핑 대상 단지 473건·법정동 31개이며 300세대 이상 222건이다. 매니페스트 최신 상태는 `SUCCESS` 21곳, `EMPTY` 1곳, `PARTIAL` 1곳, `LIST_FAILED` 7곳이다. 재시도 대상은 8곳으로 줄었다.

### 공개 호출 한도 확인과 추가 적재

- 사용자 확인 및 공공데이터포털 안내에 따르면 목록 API와 기본정보 API의 개발계정 신청 가능 트래픽은 각각 5,000회다. 이는 공개된 허용량이며 현재 인증키의 당일 사용량 또는 남은 호출량은 아니다.
- 매핑 순서 33~49번에서 대기 중이던 13개 법정동을 다시 실행했다. 11곳이 `SUCCESS`, 2곳이 `EMPTY`로 끝났고 신규 단지 124건, 기존 단지 건너뛰기 21건, 실패 0건이었다. 매핑 순서 15~49번은 모두 완료 상태다.
- 이어 50~69번 20곳 중 앞 10곳을 실행했다. 4곳 `SUCCESS`, 2곳 `PARTIAL`, 4곳 `LIST_FAILED`였다. `1120010200`은 신규 10건·기본정보 실패 6건, `1117011200`은 기본정보 실패 3건이다. 목록 실패 코드는 `1117011300`, `1117011700`, `1117011800`, `1159010500`이다. 모두 API 응답 코드 `04`였다. 목록 실패가 4곳 연속되어 자동 중단했고, 뒤의 10곳은 호출하지 않았다.
- 이 시점의 로컬 DB는 전체 단지 642건·법정동 46개, 매핑 대상 641건·법정동 45개, 300세대 이상 305건이다. 단지명·지번주소·법정동 코드·세대수의 기본 검증에서 이상은 각각 0건이다. 매니페스트 최신 상태는 `SUCCESS` 36곳, `EMPTY` 3곳, `PARTIAL` 2곳, `LIST_FAILED` 4곳이다.
- `04`는 정상 호출이 이어지다가 기본정보 일부 실패와 목록 연속 실패로 다시 나타났다. 이번 관측만으로 내부 원인 또는 호출량과의 인과관계를 확정할 수 없다. `22`·`23`은 관측되지 않았다.

### 공통 장애 여부 확인

- 50~253번 범위를 재개했으나 첫 묶음의 `1120010200`, `1117011200`, `1117011300`이 모두 목록 API `04`로 실패했다. 연속 실패 기준에 따라 작업이 중단됐고 DB에 새로 저장된 건은 없다.
- 같은 시각에 직접 GET으로 실패 코드 2곳과 이전에 성공한 `1117013100`을 조회했을 때 모두 HTTP 200의 JSON `OpenAPI_ServiceResponse` 본문에서 `04`를 반환했다. 기존 단지 `A10019921`의 기본정보 API 직접 조회도 같은 형태로 `04`였다. 두 API와 이전 성공 코드가 함께 실패해 특정 법정동이나 단일 API 경로에 한정된 문제일 가능성은 낮다.
- 같은 인증키의 공유 제약 또는 공공데이터포털·제공기관의 공통 처리 장애 중 어디인지 외부 응답만으로 특정할 수 없다. 인증키별 실제 사용량, 게이트웨이 로그, 제공기관 로그는 로컬에서 볼 수 없다. 추가 연속 호출 대신 간격을 두고 상태를 확인한다.

### 재개 중 추가 관측

- 잠시 후 이전 성공 코드의 직접 조회가 다시 `00`으로 바뀌었다. 50~69번 범위를 2곳씩 재개해 신규 단지 67건을 저장했다. 다만 일부 법정동은 부분 실패했고, 마지막에 목록 조회 4곳이 연속 `04`로 실패해 다시 중단했다.
- 같은 시점에 이전 성공 법정동 `1117013100`의 직접 조회도 HTTP 200의 `OpenAPI_ServiceResponse`에서 `04`를 반환했다. 오류 본문에는 `returnReasonCode`, `returnAuthMsg`, `errMsg` 필드가 있다. 정상과 오류가 시간에 따라 번갈아 발생한다.
- 현재 로컬 DB는 전체 단지 709건·법정동 51개, 매핑 대상 708건·법정동 50개, 300세대 이상 354건이다. 매니페스트는 `SUCCESS` 41곳, `EMPTY` 5곳, `PARTIAL` 2곳, `LIST_FAILED` 7곳이다. 실패·부분 실패 9곳과 아직 호출하지 않은 법정동이 남아 있다.

- 같은 시점의 로컬 DB는 단지 1,218건·법정동 89개이며, 권역 매핑 대상은 1,217건·법정동 88개다. 300세대 이상 단지는 651건이다. 기존 매핑 밖 단지 1건은 그대로 포함한다.
- `1168010300`의 단지 `A40010008`은 목록에는 나오지만 기본정보 API의 성공 응답 `00`에서 단지 코드·이름·주소·법정동 코드·세대수 값이 `null`이었다. 여러 번의 정상 응답에서 동일했다. 이 단지는 필수값이 없어 저장되지 않았고 해당 법정동은 `PARTIAL`이다. 임의 값으로 채우지 않았다. 이 원본 결측의 처리 정책은 사용자 판단을 기다리고 있다.

### 장시간 응답 대기와 HTTP 시간 제한

- 11차 재개에서 완료 101/254곳, 신규 단지 39건까지 진행한 뒤 한 배치가 600초 제한으로 종료됐다. 해당 배치의 한 법정동은 `SUCCESS`, 나머지 한 법정동은 종료 결과 로그를 확보하지 못해 `PROCESS_FAILED`로 기록했다. 이미 저장된 단지는 유지되며 재시도 때 건너뛴다.
- 두 외부 API의 `RestClient` 구성에 연결·응답 시간 제한이 없었다. JDK HTTP 클라이언트의 연결 제한 10초와 요청 응답 제한 30초를 명시했다. 이는 API의 `04` 자체를 해결하지는 않지만, 응답 지연 시 배치가 오래 멈추는 범위를 줄인다. 새 구성의 컴파일은 성공했고 다음 적재 배치에서 실제 동작을 확인한다.

### 원본 결측 단지의 다른 공식 응답 확인

- `A40010008`은 기본정보 API에서 `00`이어도 코드·이름·지번주소·법정동 코드·세대수 등 필수값이 `null`이었다.
- 같은 서비스의 상세정보 API는 코드와 이름을 반환하지만 지번주소·법정동 코드·세대수 필드가 없다. 목록 API는 코드·이름·법정동 코드를 반환하지만 지번주소와 세대수는 제공하지 않는다. 두 응답을 합쳐도 현재 `complex` 테이블의 필수값을 모두 구성할 수 없다.
- 따라서 임의 주소나 세대수를 사용해 저장하지 않는다. 이 단지를 원본 결측 예외로 완료 집계할지, 해당 법정동을 계속 `PARTIAL`로 둘지는 별도 정책 결정이 필요하다.
