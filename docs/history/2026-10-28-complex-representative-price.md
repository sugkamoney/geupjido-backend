# 59㎡ 대표 시세와 잠정 권역 내 순위

현재 대표 거래와 잠정 순위 기준은 문서 마지막의 `2026-10-30 다른 면적의 실제 거래와 ㎡당 잠정 순위`를 따른다.
이 문서의 이전 실행 수치와 59㎡ 이상 60㎡ 미만 조건은 당시 기준이다.

## 결정한 기준

- 단지와 권역 연결이 검증된 거래만 사용한다. 원본 거래의 `zone_id`가 단지의 현재 `zone_id`와 같아야 한다.
- 해제되지 않은 `중개거래` 중 전용면적이 `59.000000㎡ 이상, 60.000000㎡ 미만`인 거래를 고른다. 직거래와 거래 유형 미확인 거래는 원본에 남기되 대표 시세에서 제외한다.
- 가장 최근 계약일을 사용한다. 같은 날 후보가 여러 개면 거래금액 오름차순 가운데 실제 거래를 선택하고, 짝수 개면 위쪽 중앙 거래를 선택한다. 같은 금액이 여러 개면 가장 작은 거래 ID를 택한다. 원본에는 거래 시각이 없어 당일의 실제 선후는 알 수 없다.
- `complex.price`는 선택한 거래의 만원 단위 가격, `representative_area`는 그 거래의 실제 전용면적, `last_deal_date`는 계약일이다. 세 값은 한 거래에서 함께 온다. 적격 거래가 없으면 세 값을 모두 비운다.
- 같은 권역에서 대표 가격 내림차순으로 잠정 `zone_rank`를 매긴다. 가격 동률은 공동 순위이고 다음 순위는 동률 인원을 건너뛴다(1·1·3). 거래나 권역이 없으면 순위도 비운다.

## 이번 단계의 구현

`V7__expand_complex_representative_area_precision.sql`에서 `representative_area`를 원본 거래와 같은 `NUMERIC(12,6)`으로 넓혔다. 기존 Flyway 파일은 수정하지 않았다.

`ComplexRepresentativePriceService`는 연결된 거래의 적격 후보를 200개 단지씩 조회하고, 대표 거래와 잠정 순위를 한 트랜잭션에서 다시 계산한다. 따라서 거래 해제·추가 후 재실행하면 현재 유효한 거래 기준으로 결과가 바뀌고, 동일 입력 재실행의 결과는 같다. 조회 자체는 API 호출을 하지 않는다. 수동 Runner는 `COMPLEX_PRICE_RECALCULATION_ENABLED=true`로 명시적으로 켤 때만 실행한다. 일반 서버 실행에서는 비활성이다.

이 잠정 순위는 투표 기반 단지 순위가 도입되기 전까지만 사용한다. 나중에 3시간 투표 집계를 구현할 때는 주간 시세 갱신이 투표 기반 순위를 덮어쓰지 않도록 두 계산 경로를 분리해야 한다.

## 검증과 남은 범위

2026-10-28 기준 단위 테스트는 최신일·짝수 건·동액 ID·권역별 공동 순위·적격 거래 없는 단지를 확인했다. PostgreSQL·PostGIS 통합 테스트는 `중개거래`, 해제 여부, 면적 경계값, 원본 거래와 단지의 권역 일치, 6자리 실제 면적 조회를 확인했다. `./gradlew clean build`가 통과했다.

로컬 PostgreSQL에서 수동 Runner를 한 번 실행한 결과 단지 4,315개 중 대표 거래·잠정 순위가 있는 단지는 1개였다. 해당 단지 `A14072701`에는 가격 `249500`만원, 전용면적 `59.880000㎡`, 계약일 `2026-09-14`, 권역 내 잠정 순위 `1`이 저장됐다. 나머지 4,314개에는 현재 적격 연결 거래가 없다. 이는 **서비스 전 지역의 시세 적재 완료율이 아니다.** 현재 원본 거래는 용산구 2026년 9월 34건이며 검증 연결은 16건에 한정된다. 새 Flyway V7 적용과 Hibernate 스키마 검증도 로컬 DB에서 성공했다.

이 단계에서는 **이미 검증되어 연결된 거래**만 대표 시세 후보가 된다. 원본 API에는 단지 고유 ID가 없으므로 단지명만으로 연결하지 않는다. 서비스 전 지역의 초기 소급 수집과 엄격 일치 단지 연결은 아래 단계에서 수행했다.

## 서비스 지역의 API 원본 수집

초기 소급 수집은 국토교통부 아파트 매매 실거래가 API를 직접 호출한다. 권역 매핑의 시군구 코드 40개와 계약월을 조합해 기존 `ApartmentTradeImportService`로 조회·저장한다. 이 작업을 시작하는 Runner는 기본 비활성이지만, 데이터 원천은 수동 파일이 아니라 API다. 완료된 시군구·월은 Git 제외 경로 `data/trade/import-runs/local.tsv`에 남기고 재실행에서 건너뛴다. 실패한 조합은 `FAILED`로 남긴 채 다른 조합을 계속 처리한다. 실패 조합은 다음 실행에서 다시 시도한다. 결과 파일을 `build/` 밖에 두어 `clean build`로 삭제되지 않게 한다.

초기 시도 범위는 2025년 10월부터 2026년 10월까지다. API의 시군구 응답에는 서비스 권역 밖 법정동 거래도 섞일 수 있어 원본은 보존하고, 단지 연결과 대표 시세 계산에서 범위를 다시 검사한다. `apartment_trade` 적재만으로 `complex`의 가격·면적·계약일·순위가 채워지지 않는다. API에는 우리 단지 ID가 없으므로 거래와 단지를 검증해 연결한 뒤 대표값 재계산을 실행해야 한다.

기존 정책은 같은 거래 식별 키의 정상·해제 충돌 또는 해제일 불일치가 나타나면 해당 시군구·월 전체 저장을 롤백한다. 실제 은평구 2026년 9월 API 응답에서 같은 키의 정상·해제 기록 6조합이 확인됐다. 한 키가 서로 다른 실제 거래를 가리킬 가능성을 배제할 수 없어, 임의로 어느 기록을 선택하지 않는다. 이 조합의 범위와 처리 정책은 별도 검토 대상이다.

2026년 10월 28일 실행에서는 40개 시군구 × 13개월, 총 520개 조합을 모두 시도했다. `SUCCESS` 370개, 기존 정책에 따라 롤백된 `FAILED` 150개다. 로컬 DB에는 현재 `apartment_trade` 80,860건이 있으며 40개 시군구의 원본이 일부라도 존재한다. 이 중 해제되지 않은 59㎡ 타입 중개거래는 16,061건이지만, `complex_id`가 검증 연결된 원본은 기존 16건뿐이다. 따라서 `complex` 4,315개 가운데 가격·면적·계약일·잠정 순위가 채워진 단지는 여전히 1개다. 성공한 원본 수집 범위와 대표 시세 적용 범위는 서로 다르다.

전체 원본 점검에서 서비스 대상 거래는 64,547건, 대상 밖은 16,313건, 법정동 미확인은 0건이다. 연결 전 미연결 대상 중 단일 후보·이름 정확 일치는 12,196건, 이름 검토는 37,701건, 후보 없음은 12,354건, 후보 여러 개는 1,867건, 사용승인연도 불일치는 382건, 연도 미확인은 31건이다. 59㎡ 정상 중개거래로 범위를 좁히면 정확 일치 후보는 2,423건이며 대상 단지는 292개다. 연결 전 점검 결과는 로컬 `data/trade/audit-runs/local.tsv`에 보관하고 Git에서 제외한다.

## 엄격 일치 거래 연결과 로컬 적용

2026-10-29 사용자의 전체 연결 요청에 따라 `NAME_EXACT`도 아래 조건을 모두 만족하면 자동 연결하기로 했다. 거래의 서비스 대상 법정동과 단지의 10자리 법정동 코드가 같고, 지번으로 찾은 후보가 하나이며, 거래 단지명과 후보 단지명이 공백을 제외하고 같고, 거래 건축연도와 후보 사용승인연도가 같고, 단지의 현재 권역이 해당 법정동의 권역과 같아야 한다. 기존 검증 연결은 덮어쓰지 않는다. 이름이 다른 후보와 증거가 모자란 후보는 원본만 유지한다.

기본 비활성 `APARTMENT_TRADE_MATCH_AUTO_EXACT_ENABLED` 실행 경로는 미연결 거래를 500건씩 별도 트랜잭션으로 처리하고, 연결이 끝나면 대표 가격과 잠정 순위를 재계산한다. API 수집 실행과 연결 실행을 나눠 실행 순서를 명시한다. 로컬 PostgreSQL에서 미연결 거래 80,844건을 검사해 12,196건을 새로 연결했고 권역 불일치 후보는 0건이었다. 기존 연결 16건을 포함해 `apartment_trade` 80,860건 중 `complex_id`와 `zone_id`가 함께 채워진 건은 12,212건이다. 한쪽 외래 키만 채워진 거래와 단지의 현재 권역이 다른 연결은 각각 0건이다.

연결된 정상 59㎡ 중개거래는 2,426건, 대상 단지는 293개다. 재계산 후 `complex` 4,315개 중 293개에 `price`, `representative_area`, `last_deal_date`, 잠정 `zone_rank`가 함께 채워졌다. 가격이 있는 모든 단지는 조건에 맞는 연결 거래 한 건을 근거로 가진다. 4,022개에는 현재 적격 연결 거래가 없어 값을 비워 둔다. 미연결 대상 거래 중 이름 검토 37,701건, 후보 없음 12,354건, 후보 여러 개 1,867건, 연도 불일치 382건, 연도 미확인 31건은 별도 검토가 필요하다. API 수집에서 실패한 시군구·월 150조합도 아직 남아 있으므로 이 결과를 서비스 전 지역의 완료 상태로 해석하지 않는다.

표시 단위와 투표 급지 변동 폭은 #100에서 정하지 않는다. 투표 알고리즘을 구현할 때 예상 사용자 수와 예상 투표량을 보고 정한다.

## 2026-10-29 재점검: 원본 보존과 누락 원인

사용자가 확정한 수집 범위는 현재 권역 매핑에서 도출한 **40개 시군구의 API 응답 전체**다. 응답에 포함된 서비스 권역 밖 법정동 거래도 `apartment_trade`에 원본으로 보존한다. 다른 전국 시군구로 수집 대상을 넓히지는 않는다. 읽기 전용 전체 점검에서 원본 80,860건 중 서비스 대상 64,547건, 대상 밖 16,313건, 법정동 미확인 0건이었다. 대상 밖 거래는 단지·권역에 연결하지 않았으며, 거래의 계약일·가격·면적·층·건축연도·지번·거래 유형은 80,860건 모두 채워져 있다. `apartment_dong`은 API에서 선택적으로 오는 값으로 21,933건이 비어 있다.

기존 실패 시군구·월 150조합을 API에서 모두 재시도했으나 150개 모두 다시 롤백됐다. 원인은 `CANCELED_TO_NORMAL` 68개, `CANCELLATION_DATE_MISMATCH` 82개로, API 호출 실패는 0개였다. 현재 거래 고유 키에는 공공 API의 고유 거래 ID가 없으므로 같은 키가 실제로 다른 거래를 뜻하는지 구별할 수 없다. 재시도 결과 파일은 실패 사유 코드를 기록하며, 종전 결과 행은 사유가 빈칸으로 남는다. 성공 370개, 실패 150개와 원본 80,860건은 그대로다.

현재 단지 4,315개는 모두 `zone_id`, 법정동 코드, 좌표를 가진다. 이 중 3,495개는 연결 거래가 한 건도 없고, 527개는 연결 거래가 있지만 정상·중개·59㎡ 조건을 만족하는 거래가 없으며, 293개에 대표 시세와 잠정 순위가 있다. 이름이 달라 자동 연결하지 않은 거래 37,701건은 법정동·지번·원본명·후보 단지 ID 기준 2,359개 검토 조합으로 묶을 수 있다. `scripts/trade/summarize_match_audit.py`가 최신 거래별 점검 TSV에서 이 목록과 시군구별 상태를 만든다. 이 목록 자체는 연결 승인 기록이 아니다.

검토 목록에 단지 마스터와 59㎡ 적격 거래 ID를 결합하면 933개 이름 검토 조합의 7,979건이 정상·중개·59㎡ 거래다. 후보 단지는 920개이며 그중 919개에는 현재 대표 가격이 없다. 따라서 이 조합은 가격 적용 범위에 큰 영향을 주지만, 동일 지번의 단일 후보라는 사실만으로 원본명과 단지 마스터가 같은 단지라고 확정하지 않는다. 후보의 실제 이름·지번주소·도로명주소·사용승인일·권역을 함께 담은 로컬 검토 파일은 `data/trade/audit-runs/trade-name-review-groups.tsv`에 Git 제외 상태로 남겼다.

전체 미연결 거래는 5,179개 검토 조합으로 묶인다. 이름 검토 2,359조합(거래 37,701건, 적격 59㎡ 7,979건), 후보 없음 2,725조합(12,354건, 적격 2,044건), 복수 후보 61조합(1,867건, 적격 347건), 연도 불일치 18조합(382건, 적격 187건), 연도 미확인 16조합(31건, 적격 6건)이다. `trade-unlinked-groups.tsv`에서 후보 판정별로 확인할 수 있다. 적격 수는 거래의 정상·중개·59㎡ 조건만 검사한 수이며, 단지 연결이 확정됐다는 뜻은 아니다.

## 충돌 건 분리와 안전한 거래 우선 저장

2026-10-29 사용자는 기존에 실패한 월을 계속 재시도하는 대신, **충돌 없는 거래를 먼저 저장하고 충돌 건은 함께 하나씩 검토**하기로 했다. 수집 대상은 기존 40개 시군구 응답의 모든 법정동 거래다.

소급 수집은 월별 응답 전체를 읽은 뒤 현재 고유 키(시군구·법정동명·단지명·계약일·전용면적·층·가격)로 묶는다. 한 응답 안에서 같은 키의 정상·해제 상태가 섞이거나 해제일이 다르면 그 키의 모든 응답을 보류한다. 기존 DB에 저장된 해제 거래와 새 정상 거래가 충돌하거나 해제일이 다를 때도 해당 키를 보류한다. 정상 거래가 처음 해제 거래로 다시 제공되고 키에 다른 모순이 없으면 기존 규칙대로 해제 갱신을 허용한다. 다른 키의 거래는 같은 트랜잭션에서 저장한다.

보류 응답은 새 Flyway V8의 `apartment_trade_conflict`에 응답 순서, 주소·거래 항목, 충돌 사유, 기존 저장 거래 ID와 함께 보존한다. 기존 거래가 보류 키에 해당하면 `review_status='OPEN'` 동안 대표 가격 후보에서 제외한다. 월별 결과는 `PARTIAL`로 남기고 기본 재실행에서 건너뛴다. 원본 데이터의 고유 거래 ID가 없으므로 서로 다른 실제 거래가 같은 키를 공유할 가능성은 이 작업만으로 해소되지 않는다. 충돌 검토 후 명확한 증거가 있는 건에 대해서만 식별 규칙이나 데이터를 변경한다. 수동 월별 적재의 기존 전체 롤백 동작은 그대로 유지한다.

### 로컬 적용과 대조 결과

기존 `FAILED` 150개 시군구·월을 다시 호출한 결과 모두 `PARTIAL`로 처리됐고 실패는 0개다. 새 응답 63,161건은 신규 저장 58,923건, 기존 중복 건너뛰기 310건, 보류 3,928건으로 정확히 합산된다. 보류 응답은 1,908개 거래 식별 키에 해당하며, 원본 내 정상·해제 상태 충돌 3,880건/1,884키, 해제일 충돌 48건/24키다. 이번 재수집에서 기존 저장 행과 직접 충돌한 건은 0건이었다. 전체 결과는 `SUCCESS` 370개, `PARTIAL` 150개이며, 로컬 `apartment_trade`는 80,860건에서 139,783건으로 증가했다.

새 거래에 기존 엄격 일치 규칙을 적용해 11,033건을 추가 연결했다. 연결된 거래는 총 23,245건이고 연결 단지와 권역이 다른 행은 0건이다. 대표값 재계산 후 `complex` 4,315개 중 310개에 가격·면적·계약일·잠정 순위가 함께 있으며, 나머지 4,005개에는 적격 연결 거래가 없다. `score`는 아직 투표 전이라 전부 비어 있다. 전체 읽기 전용 점검에서 서비스 대상 거래 112,850건, 대상 밖 26,932건, 법정동 미확인 1건을 확인했다. 미확인 거래는 API 응답의 시군구 코드 `11290`과 법정동명 `청량리동`이 함께 온 행이다. 로컬 법정동 기준표에서는 청량리동이 `11230`으로 분류돼 원본만 보존하고 단지 연결은 보류했다.

로컬 검토 자료는 Git에서 제외한 `data/trade/audit-runs/trade-conflict-review-20261029.tsv`와 `after-partial-20261029.tsv`에 저장했다. 충돌 검토 TSV는 헤더를 제외하고 3,928행이다. 충돌 해소 여부나 어느 응답이 실제 거래인지 이 단계에서 자동 판정하지 않았다. 로컬 PostgreSQL·PostGIS 통합 테스트, 전체 `./gradlew clean build`, Flyway V8 적용 및 Hibernate 스키마 검증이 통과했다.

충돌 키 1,908개 중 1,774개는 정상 1건·해제 1건의 짝이고, 134개는 한쪽 또는 양쪽에 여러 응답이 있다. 정상 59㎡ 중개거래를 포함하는 키는 373개이며, 그중 347개가 1:1 짝이다. 첫 검토 사례로 `왕십리풍림아이원`(하왕십리동 1061, 2025-10-13, 59.936㎡, 8층, 12억 8,000만원)은 정상 응답에 `102동`이 있고 해제 응답에는 동 번호가 없으며 해제일은 2026-01-07이다. [국토교통부 API 안내](https://www.data.go.kr/data/15126469/openapi.do)에 따르면 동 정보는 소유권 이전등기가 완료된 건에만 추가 공개된다. 따라서 이 동 번호 차이만으로 서로 다른 실제 거래라고 확정할 수 없다. 같은 키에 정상·해제 두 응답이 존재하는 이유도 API에 거래 고유 ID가 없어 아직 확정하지 않았다.

### 확정한 가격 사용 기준과 재실행 검증

[국토교통부 전자계약 FAQ](https://irts.molit.go.kr/usr/brd/bscbrd/faq/RtecsFaqList.do)에 따르면 최종 서명 후 계약을 수정하려면 해제하고 다시 작성해야 한다. 이는 정상·해제 응답이 함께 나타나는 가능한 원인이지만, 현재 API 응답만으로 해당 기록이 전자계약인지, 두 기록이 같은 계약인지 확인할 수 없다. 따라서 충돌 없는 정상 거래만 가격에 사용하고, 해제 거래와 같은 키의 정상·해제 충돌 건은 가격에서 제외한다. 다른 적격 59㎡ 거래가 없으면 단지 가격을 비워 둔다. 보류 건은 가격에 영향을 주는 사례부터 증거를 대조한다. 아파트 동 번호는 거래 식별 키와 가격 계산에 사용하지 않으며, 현재 수집된 원본 검토 항목으로만 보존한다.

2026-10-29 성동구(`11200`) 2025년 10월을 별도 결과 파일로 다시 API 조회했다. 392건 중 357건은 이미 저장된 거래라 건너뛰고 35건은 다시 보류했으며 신규 저장·실패는 0건이었다. 재실행 전후 `apartment_trade` 139,783건, 열린 충돌 3,928건, 가격이 있는 단지 310개, 연결된 거래 23,245건이 그대로 유지됐다. 충돌 보관 테이블의 해당 시군구·월 행도 35건으로 중복되지 않았다. PostgreSQL·PostGIS 통합 테스트와 `./gradlew clean build`를 다시 통과했다.

### 같은 지번의 임대·분양 단지와 매매 거래 연결

공동주택 기본정보 API의 `codeSaleNm`을 새 Flyway V9의
`complex.sale_type`에 원문 그대로 저장한다. 같은 지번에 임대와 분양
단지 ID가 함께 있으면 임대 전용만 후보에서 빼고, 남은 후보의 법정동·지번,
건축·사용승인연도와 권역을 확인한다. `혼합`은 분양이 포함될 수 있어
임대 전용으로 취급하지 않는다. 이름이 조금 다르다는 이유만으로 임의
연결하지 않고, 확인된 두 원본명·지번·연도·단지 ID 조합만 별칭으로 승인했다.

- `신당동 844 · 남산타운`: 임대 `A10045301`, 분양 `A10045302`.
  승인 별칭은 `A10045302`다.
- `황학동 2545 · 롯데캐슬`: 임대 `A10044001`, 분양 `A10044002`.
  승인 별칭은 `A10044002`다.

로컬 DB에서 기본정보 API 100건 시험 적재 중 79건을 갱신했고 21건은
오류 코드 `04`가 반복되어 실패했다. 그 뒤 비교용 단지까지 같은 `04`를
반환해 전체 보충은 중단했다. [공공데이터포털 오류 코드 안내](https://www.data.go.kr/tcs/dss/selectErrCodePopupView.do)는 `04`를 요청 방식 문제 또는 기관 API 응답 처리 실패로 설명한다. 같은 URL·인증키로 앞선 조회가 성공했지만 이번 오류의 정확한 원인은 아직 확인되지 않았다. 앞선 공식 응답에서 이미 확인한 위 네 단지는
로컬 DB에 임대·분양을 반영했다. 현재 분양형태가 있는 단지는
4,315개 중 125개(`분양` 74, `임대` 30, `혼합` 21)다. 미확인 단지는
임대라고 추정하지 않는다.

자동 연결 재실행에서 확인된 임대 전용 단지의 과거 연결 223건을 해제했다.
원본 거래는 보존했다. 신당 사례 133건과 황학 사례 139건은 각각 분양
단지 ID에 연결됐고, 두 단지의 대표 가격과 권역 내 잠정 순위가 채워졌다.
전체 연결 거래는 23,294건, 가격·순위가 있는 단지는 312개다.
전체 분양형태 보충과 다른 이름 차이의 검토는 아직 끝나지 않았다.

공식 [K-apt 공동주택 단지 기본 정보 파일](https://www.data.go.kr/data/15073271/fileData.do)도 분양형태와 단지코드를 제공하지만 주간 엑셀 참조 자료이며, 안내문은 현 시점의 정확한 값에는 OPEN API를 사용하라고 한다. 제공된 직접 다운로드 주소는 현재 일반 HTTP 요청에 파일 대신 접근 거부 안내를 반환했다. 따라서 오래된 파일 값으로 미확인 단지를 임의 보충하지 않았다.

### 단지 코드와 거래 원본의 연결 범위 재확인

`complex.id`는 공동주택 단지 API의 `kaptCode`다. 반면 현재 사용하는 기본
아파트 매매 실거래가 API는 시군구 코드와 계약월로 조회하며, 실제 응답에
`kaptCode`가 없다. 단지를 코드로 조회·저장한 사실만으로 개별 거래의
`complex_id`가 결정되지는 않는다. 상세 실거래가 API는 별도 서비스이며
현재 인증키로 호출하면 HTTP 403과 오류 코드 `30`을 받았다. 추가 필드가
두 원천의 단지 ID를 직접 연결하는지는 정상 응답과 기술문서 확보 후 검증한다.

2026-10-29 로컬 감사에서는 원본 거래 139,783건 중 23,294건만 단지와
권역에 연결돼 있었다. 같은 지번에 단지 후보가 여러 개인 거래 2,586건
중 133건은 거래명과 같은 이름의 후보가 딱 하나였다. 해당 6개 후보의
`codeSaleNm`을 공동주택 기본정보 API로 다시 조회해 모두 `분양`임을 확인했다.
그 뒤 이름·건축/사용승인연도·권역까지 검증하는 선택 규칙으로 133건을
추가 연결했다. 재계산 결과 가격과 잠정 권역 순위가 있는 단지는 314개다.

지번 표기만 다른 경우에는 숫자 본번·부번을 비교한다. 예를 들어 `417`과
`0417-0000`은 같은 숫자 지번으로 본다. 이 완화 규칙은 분양형태가 확인된
단지에만 적용한다. 실제 지번 숫자가 다른 거래는 자동 연결하지 않는다.
미연결 감사 자료와 단지 마스터를 대조한 결과, 후보 없음 거래 중 152조합
4,872건은 같은 법정동·권역에 이름이 같은 단지가 하나 있지만 주소 지번이
달랐다. `trade-address-review-groups.tsv`를 수동 검토용으로 만들었으며,
공식 주소·필지 확인 전에는 연결하지 않는다. 서비스 범위 밖 26,932건과
법정동 미확인 1건에는 현재 권역 매핑으로 `zone_id`를 줄 수 없다.

같은 숫자 지번의 표기 차이를 반영하고 분양형태가 확인된 후보만 선택해
재실행한 결과 283건을 추가 연결했다. 예를 들어 올림픽파크포레온은 거래
지번 `633`과 단지 주소의 `633-`을 같은 본번·부번으로 확인한 후 114건을
연결했다. 그다음에는 이미 검증된 거래와 시군구·법정동명·지번·원본명·
건축연도가 완전히 같은 거래를 다른 계약월에서도 재사용했다. 기존 연결이
한 단지·권역으로만 수렴하고, 현재 단지의 법정동·권역·사용승인연도가
일치하며 임대 전용이 아닌 경우에만 156건을 추가 연결했다. 원본명이나
지번이 바뀐 거래는 이 재사용 규칙에 해당하지 않는다.

최종 로컬 DB에는 139,783건 중 23,866건이 단지·권역과 함께 연결돼 있고,
`complex` 4,315개 중 319개에 대표 가격과 잠정 순위가 있다. 부분 연결
행과 단지의 현재 권역과 다른 연결은 각각 0건이다. 분양형태 보충은 이번
실행에서 6개 우선 후보와 추가 80개 단지를 갱신해 분양형태가 있는 단지는
302개가 됐지만, 반복된 API 오류
코드 `04` 때문에 아직 전체 완료가 아니다. 뒤쪽 단지를 재개할 수 있도록
API 호출을 순차화하고 `04`가 연속 3건이면 중단하도록 했다.
`./gradlew clean build`와 로컬 PostgreSQL·PostGIS의 Flyway·Hibernate
검증이 통과했다. 빌드 후 최종 감사 자료를 다시 만든 결과 미연결 거래는
115,917건이며, 그중 이름은 같지만 지번이 다른 단일 후보 검토 목록은
135조합 4,557건이다. 최종 감사의 나머지 판정은 후보 없음 21,039건,
이름 검토 64,838건, 복수 후보 2,458건, 연도 불일치 589건,
연도 미확인 60건이다. 이 수치는 서비스 대상 미연결 거래만 분류한 것이며,
서비스 범위 밖 26,932건과 법정동 미확인 1건은 별도다.

### 상세 실거래가 API 승인 후 도로명 주소 대조

`A12070101`, `호계동 1055-1 무궁화코오롱` 22건은 `A43179103`으로
연결했다. 같은 지번의 다른 K-apt 단지(`돈의문센트레빌215동`,
`무궁화건영`)가 있으므로 지번만으로 선택하지 않았다. 적용 전 거래·단지
테이블을 로컬 덤프로 백업했다. [검증 SQL](../../scripts/trade/link_verified_name_lot_20261030.sql)은
후보 유일성, 예상 원본 건수, 미해결 충돌, 적용 후 두 외래 키 일치를
트랜잭션 안에서 검사한다. 실제 실행은 `UPDATE 38`, `COMMIT`으로 끝났다.
이름이 다른 `상도동 211-1 약수맨션` 1건은 지번·연도·분양형태만으로
동일 단지라고 확정하지 않아 연결하지 않았다.

대표 시세 Runner를 다시 실행한 결과 가격·실제 면적·계약일·잠정 순위가
함께 있는 단지는 **1,794→1,796개**다. 새로 가격이 생긴 두 단지는
돈의문센트레빌(150,000만원, 59.980000㎡, 2026-07-17)과
무궁화코오롱(79,500만원, 59.340000㎡, 2026-09-17)이다. 거래 연결은

4,715개를 현재 저장된 거래 기준으로 나누면 연결 거래 없음 2,378개,
연결 거래는 있으나 58㎡ 이상 61㎡ 미만 거래 없음 2,322개,

주소·단지 연결이 늘어도 적격 거래가 없는 단지의 가격과 순위는 비어 있다.
기존 가격 1,796개는 모두 동일한 실제 정상 중개거래의 가격·면적·날짜를
참조하고, 권역 내 순위는 가격 내림차순과 일치한다.

남은 미연결 거래에는 권역 밖 원본, K-apt에 대응 단지가 없는 거래,

### 2026-10-30 대표 거래가 없는 단지의 면적 범위 확대

우선순위는 단지별로 적용한다. 정상 중개거래 중 전용면적 `58㎡ 이상
61㎡ 미만`인 거래가 있으면 기존처럼 이 범위에서 최근 계약일을 고르고,
같은 날 거래의 상위 중앙 가격을 대표 거래로 선택한다. 이 범위에 적격
거래가 없는 단지만 `44㎡ 이상 65㎡ 이하`의 같은 조건으로 다시 찾는다.
해제된 거래, 미해결 충돌, 단지와 권역 연결이 일치하지 않는 거래는 두
단계 모두에서 제외한다. 선택된 거래의 실제 전용면적을
`representative_area`에 기록한다. `zone_rank`는 선택된 가격을 기준으로
권역마다 다시 계산한다.

로컬 DB 재계산 결과 가격·실제 면적·계약일·잠정 순위가 모두 있는
단지는 **1,796개에서 2,123개**로 늘었다. 신규 327개만 확대 범위를
사용했고, 기존 58~61㎡ 가격 단지 1,796개는 우선 범위를 유지했다.
네 값의 부분 저장, 허용 면적 범위 밖 저장, 가격 기준 순위 불일치는
각각 0건이다. 재계산 전 `complex` 테이블은 로컬 임시 덤프로 백업했다.

남은 가격 공백 **4,388개**의 원인은 연결 거래 없음 2,378개,
연결 거래는 있으나 44~65㎡ 거래 없음 1,990개, 해당 면적 거래가
전부 해제됨 5개, 정상 중개거래 없음 15개다. 이들은 면적 범위
확대만으로 가격을 만들 수 없다. 현재 공백 상세 목록은 Git 제외 경로
`data/trade/audit-runs/complex-price-gaps-after-fallback-20261030.csv`에
있고, 위 [재생성 SQL](../../scripts/trade/report_complex_price_gaps.sql)은
새 범위로 갱신했다. 앞 절의 공백 수치는 범위 확대 전 기록이다.

### 2026-10-30 다른 면적의 실제 거래와 ㎡당 잠정 순위

44~65㎡ 거래가 없는 단지도 실제 거래를 활용하기로 했다. 정상 중개거래의
58~61㎡, 44~65㎡, 그 밖의 양수 면적 순서로 확인하고, 그다음 정상
직거래의 같은 면적 순서를 적용한다. 다른 면적에서는 59㎡와의 거리,
계약일 순으로 선택한다. 해제 거래와 미해결 원본 충돌은 제외한다.
`representative_area`에는 선택한 거래의 **실제 면적**을 저장한다.
면적이 다른 단지들의 단순 총액을 비교하지 않도록 초기 `zone_rank`는
대표 가격을 실제 면적으로 나눈 ㎡당 가격의 내림차순으로 계산한다.
이 순위는 투표 기반 순위가 도입되기 전의 잠정값이다.

로컬 PostgreSQL 재계산에서 6,511단지 중 가격·면적·계약일·잠정
순위가 모두 있는 단지는 **5,337개**다. 나머지 **1,174개**는 현재
연결된 거래 자체가 없는 단지 1,168개와 연결 거래가 모두 해제된
단지 6개다. 이 결과는 API 적재와 단지 연결 상태가 바뀌면 달라진다.
재계산 전 DB 덤프는 로컬 임시 경로에 보관했다. 가격 공백은
[`report_complex_price_gaps.sql`](../../scripts/trade/report_complex_price_gaps.sql)로
다시 확인할 수 있다.

단지 기본정보와 거래 API의 이름은 같은 단지에서도 다를 수 있다.
예를 들어 K-apt 단지 `A13523003`은 `수서가람`이고, 일원동 735의
실거래 원본 6건은 `가람`이다. 이 6건의 `complex_id`와 `zone_id`는
이미 해당 단지와 `gangnam-irwon`으로 연결되어 있다. 따라서
`complex.name`을 거래 API의 짧은 이름으로 일괄 교체하지 않는다.
이름 차이는 검증된 단지 연결의 별칭으로 다루고, 법정동·지번·건축연도·
도로명 주소 등과 함께 대조한다. 이름만으로 자동 연결하지 않는다.

### 2026-10-30 가격 공백 단지 1,168개 재조사

당시 가격 공백 1,174개 중 연결 거래가 아예 없던 1,168개를 로컬 원본과
대조했다. 기존 수집 범위는 2025년 10월~2026년 10월이어서, 그 기간에
해당 지번의 거래가 없다는 사실만으로 단지에 거래가 전혀 없다고 결론 내릴
수 없었다. 가격이 없는 단지에 한해 K-apt 기본정보 API의 분양형태를
조회하고, 확인된 임대 전용 단지는 거래 연결을 해제한 뒤 제거했다.
기본정보 API는 일부 단지에서 오류 코드 `04`를 반환하므로 미확인 단지는
분양이나 임대로 추정하지 않고 남긴다.

이어서 권역 매핑의 62개 시군구에 대해 2025년 1~9월 실거래 원본
558개 조합을 소급 수집했다. 실패 조합은 0개이며 신규 원본 151,850건이
저장됐다. 동일 식별키의 상태·해제일 충돌 20,506건은 별도 충돌 테이블에
남기고 대표 가격에서 제외했다. 그다음 검증된 원본 식별 조합과 법정동·
지번·건축연도·단지명을 대조해 거래 108,585건을 추가 연결했다. 단지명
끝의 `아파트`와 공백 차이는 후보를 유일하게 결정할 수 있을 때만
동등하게 비교한다. 지번 후보가 여럿이면 분양형태까지 확인한다.

첫 재계산에서 전체 6,492단지 중 가격·실제 면적·계약일·잠정 순위가
함께 있는 단지는 5,382개, 공백은 1,110개였다. 2025년 1~9월 상세
API의 도로명주소와 단지 주소를 단독 후보·법정동·건축연도·권역으로
재검증해 125건을 더 연결했다. 이때 35단지에 대표 가격이 새로 생겨
5,417개가 채워졌다. 상세 주소만으로 결정할 수 없는 주소 공유·연도
불일치·원본 중복은 연결하지 않았다. 추가로 기본정보 API에서 확인된
임대 전용 단지를 제거한 현재 단지 수는 6,477개이고 가격 공백은
1,060개다. 이 수치는 다음 상세 식별값 대조 전 중간 결과다.

공백 목록은 `scripts/trade/audit_unpriced_complexes.py`로 다시 만들 수
있으며, Git 제외 경로 `data/trade/audit-runs/unpriced-complexes.csv`에
단지 ID, 양쪽 주소, 지번, 사용승인연도, 분양형태, 이름·연도가 같은
거래의 다른 지번과 원인 분류가 기록된다. 이 원인 분류는 현재 저장된
거래와 K-apt 지번의 문자열 비교이므로 실제 거래 부재나 동일 부지
여부를 확정하는 자료로 취급하지 않는다.

2024년 1~12월의 744개 시군구·월 조합도 모두 조회했다. 원본
180,000건 중 신규 167,006건을 저장했고, 기존 원본 1,050건은
건너뛰었으며, 식별키·상태 충돌 11,944건은 보류 기록으로 남겼다.
수집 실패 조합은 없었다. 엄격 일치로 113,389건, 상세 도로명 주소
재검증으로 49건을 추가 연결했다. 상세 API의 단지 식별값으로는
추가 연결 가능한 건이 없었다.

2024년 수집 직전 6,477단지 중 가격이 있던 단지는 5,417개였다.
2024년 조회·연결 후 실제로 가격이 새로 생긴 단지는 **7개**다.
기존 가격 129건은 합의한 58~61㎡ → 44~65㎡ → 기타 면적 우선순위에
따라 더 오래된 2024년 거래로 바뀌었다. 현재 규칙에는 거래일의
최대 경과 기간이 없으므로, 과거의 우선 면적 거래가 최신의 다른
면적 거래를 대체할 수 있다. 오래된 실거래를 더 소급 수집하면 이
현상이 늘 수 있어, 2023년 이전 자동 확장은 진행하지 않았다.

가격이 없는 단지를 대상으로 K-apt 분양형태를 재조회해 추가로
**임대 전용 526개**를 확인하고 연결을 해제한 뒤 제거했다. 두 차례
조회 후에도 기본정보 API에서 확인되지 않은 단지는 24개이며 분양·임대
여부를 추정하지 않았다. 분양형태 확정 후 엄격 일치 연결을 재실행해
841건을 연결했다. 상세 도로명주소 대조를 전체 수집 기간에 다시
적용해 8,004건을 추가 연결했고, 검증된 원본 식별 조합으로 68건을
더 연결했다. 이 세 단계로 가격이 새로 생긴 단지는 67개다. 상세
`aptSeq`만으로 새로 연결되는 건은 없었다.

최종 로컬 DB는 **5,951단지**, 가격·실제 면적·계약일·잠정 권역
순위가 모두 있는 단지는 **5,491개**, 가격 공백은 **460개**다.
2024년 소급 수집 직전 대비 74단지에 가격이 새로 생겼고, 임대 전용
526단지를 제거했다. 네 필드 중 일부만 채워진 단지는 0개이며,
가격 공백 460개는 분양 378개, 혼합 56개, 분양형태 미확인 24개,
사택 및 관사 등 2개다. 분양형태 조회는 가격 공백 단지만 대상으로
했으므로 가격이 이미 있는 단지의 분양형태는 별도 검증이 필요하다.

가격 공백 460개의 로컬 감사 분류는 같은 지번 거래 없음 257개,
이름 차이 또는 공유 부지 136개, 사용승인연도 없음 25개, 같은
사용승인연도 거래 없음 25개, K-apt 지번 추출 불가 12개,
해당 법정동 거래 없음 3개, 적격 연결 거래 없음 1개, 같은 이름·연도·
지번의 거래가 다른 단지에 연결된 사례 1개다.
이 분류는 자동 연결을 허용하는 근거가 아니다. 확인되지 않은 단지에
다른 단지의 거래나 추정 가격을 대입하지 않는다.

공유 지번 사례로 도봉동 641에는 K-apt `A13201208`(서원아파트)과
`A13275302`(도봉서원제2)가 별도 단지다. 서울시 단지정보에도
