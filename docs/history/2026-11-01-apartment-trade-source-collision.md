# 실거래 원본의 정상·해제 충돌 처리

## 배경

2026-09 용산구 매매 API는 문배동 리첸시아용산B의 계약일·가격·면적·층이
같은 행을 정상과 해제로 각각 반환했다. 기존 거래 식별 키는 두 행을 한
거래로 보았고, DB에는 해제 행만 남아 있었다. 정상 원본에는 103동과
2026-10-15 등기일, 해제 원본에는 2026-10-08 해제일이 있다.

## 판단과 규칙

현재 수집하는 API 항목에는 이 두 행을 연결하는 고유 거래 ID가 없어 동이나 등기일
하나만으로는 별도 계약을 확정할 수 없다. 같은 계약 조건의 정상·해제 행이
함께 나타나고, 정상 행에 동과 등기일이 있으며, 해제 행에는 등기일이 없고,
정상 등기일이 해제일보다 늦으면 서로 다른 원본으로 보존한다. 이는
날짜 순서와 공개된 동 정보에 근거한 판정이며, 원본의 법적 동일성을
증명하는 규칙은 아니다. 조건이 부족하거나 기존 등기일과 충돌하면
검토 대상으로 남긴다.

같은 계약 조건에는 정상 행과 해제 행을 각각 최대 한 건만 허용한다.
해제 행은 대표 가격 후보에서 제외한다. 이미 기록된 충돌은 두 행이
정상적으로 저장된 뒤 `RESOLVED`로 바꾸고 이력을 유지한다. 다시
수집해도 같은 행을 추가하지 않는다.

## 대안과 영향

- 해제 행을 정상 행으로 덮어쓰면 기존 해제 사실을 잃는다.
- 등기일 또는 API 응답 순서만 유일 키로 삼으면 값이 늦게 채워지거나
  순서가 바뀔 때 같은 행이 중복될 수 있다.
- 정상·해제 상태를 유일 키에 추가하고, 저장 서비스에서 날짜 근거를
  검사한다. DB는 동일 상태 중복을 막고 서비스는 무근거 상태 분리를 막는다.

이 규칙은 원본 API에 고유 거래 ID가 생기면 재검토한다. 다른 시군구·월의
충돌도 같은 조건을 충족하는 경우에만 자동 분리된다.

## 전체 주간 실행의 미해결 충돌 점검

2026-11-01 로컬 전체 실행(2026-09~11월, 62개 시군구)에서 기록한
`PARTIAL` 82조합의 충돌 원본 431행은 거래 조건별로 215묶음이다.
동일 조건은 시군구·법정동·단지명·계약일·면적·층·가격으로 판단한다.

| 원인 | 거래 조건 | 원본 행 | 확인 내용 |
|---|---:|---:|---|
| 정상·해제 상태 동시 반환 | 213 | 427 | 212묶음은 정상 1행과 해제 1행, 1묶음은 정상 1행과 해제 2행 |
| 서로 다른 해제일 반환 | 2 | 4 | 각 묶음에 해제 2행, 해제일이 다름 |

상태 충돌 213묶음 가운데 123묶음은 기존 저장 거래 123건과 연결된다.
이 중 12건은 정상 거래이고 111건은 해제 거래다. 정상 거래 12건 중
11건은 서비스 단지에 연결되어 있으며, 열린 충돌이므로 대표 가격
후보에서 제외된다. 충돌과 연결된 기존 거래의 서비스 단지는 중복을
제외하면 99곳이다. 나머지 상태 충돌 90묶음과 해제일 충돌 2묶음에는
연결된 기존 저장 거래가 없다.

실제 원본을 보면 중구 신당동 `약수하이츠`는 같은 계약 조건의 정상·해제
행에 등기일과 동 정보가 모두 없다. 도봉구 방학동 `신동아아파트1`은
정상 행에 동 `14`와 등기일 2026-09-22가 있지만 해제일도
2026-09-22여서 '해제일 이후 등기' 조건을 충족하지 않는다. 강서구
내발산동 `명덕`은 정상 등기일이 해제일보다 늦지만 동 정보가 없어
별도 계약이라고 자동 확정할 수 없다. 부천시 중동 `보람마을(아주)`는
같은 조건에 정상 1행과 해제일이 서로 다른 해제 2행이 있다. 안산시
건건동 `건건e-편한세상`에는 정상 행 없이 해제일이 다른 해제 2행이
있다.

현재 수집 모델에는 계약을 고유하게 식별하는 원본 번호가 없다. 따라서
동일 조건의 정상·해제 행을 일괄적으로 각각 유효 거래로 저장하거나,
둘 중 하나를 삭제하는 규칙은 근거가 부족하다. 431행은 `OPEN`으로
보존하고 대표 가격에서 제외한다. 다음 검토에서는 원본 식별 자료를
확보할 수 있는지 확인하고, 확보되지 않으면 해당 충돌을 보류 상태로
유지한다. 2026-11-01 최초 전체 실행의 `NEEDS_REVIEW`는 수집 실패가
아니라 원본을 확정하지 못한 상태였다. 이후 완료 판정을 분리해 수집
실패와 이번 조합의 연결·권역 이상이 없으면 `COMPLETE_WITH_CONFLICTS`로
표시한다. 충돌 원본의 검토 상태는 계속 `OPEN`이다.
