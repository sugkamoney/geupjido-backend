# 지도·월드컵 패널 백엔드 점검

관련 이슈: [#169](https://github.com/sugkamoney/geupjido-backend/issues/169)

## 확인 범위와 결과

2026-11-14 로컬 PostgreSQL·PostGIS에서 지도 조회, 월드컵 게임·권역 선택·타임라인 통합 테스트 22개와 급지 발행 통합 테스트 1개가 통과했다. 테스트의 DB 변경은 트랜잭션 롤백을 사용했고, 공유 개발 RDS에는 검증용 투표를 쓰지 않았다.

배포 서버에서는 읽기 요청으로 health, 지도 상태·시군구·권역·단지 핀·권역 상세·검색, 월드컵 권역 목록·타임라인을 확인했다. 전체 지도 범위의 조회 건수는 시군구 62개, 권역 282개, 단지 핀 5,610개였다. 권역 상세는 경계와 단지 목록을 반환했고, 검색은 일치 결과와 빈 결과를 모두 반환했다. 월드컵 타임라인은 전체 및 권역 필터가 동작했다. 없는 권역, 잘못된 지도 범위, 게임 쿠키가 없는 요청의 오류 응답도 확인했다. 이 점검에서는 배포 서버의 게임 시작이나 투표 요청을 실행하지 않았다.

## 수정한 설정

개발 서버의 `dev` 프로필에 월드컵 급지·순위 집계 예약 설정이 없어 예약 작업이 생성되지 않았다. 당시 지도 상태 응답은 `nextScheduledAt=null`, `lastCompletedAt=null`이었고, 타임라인에는 선택 기록이 있었다. 타임라인은 원시 선택 기록이고 지도 상태의 표 수는 발행된 유효표 스냅샷이므로 두 값의 차이는 정상이다. 그러나 `nextScheduledAt=null`은 개발 서버에 예약 집계가 꺼진 상태임을 보여줬다.

`application-dev.yml`에 한국 시간 0·3·6·9·12·15·18·21시 예약을 기본으로 켰다. 로컬 프로필의 기본값은 꺼진 상태로 유지하고, 개발 서버에서도 `WORLDCUP_RATING_SCHEDULE_ENABLED=false`로 중지할 수 있다. 이 변경은 배포 전까지 서버에 반영되지 않는다. 배포 후 지도 상태의 `nextScheduledAt`이 표시되는지 확인하고, 첫 예약 실행 후 `lastCompletedAt`과 집계 로그를 확인해야 한다. 조건을 만족하지 않는 권역은 예약이 실행되어도 투표 기반 급지로 전환되지 않는다.

변경한 JAR를 로컬 PostgreSQL에 연결해 `dev` 프로필로 실행했을 때 앱이 정상 시작됐고, 지도 상태의 `nextScheduledAt`이 다음 한국 시간 18시를 가리켰다. 확인 후 로컬 프로세스를 종료했다. 전체 `./gradlew clean build`도 성공했다.

## 시안 계약의 남은 범위

디자이너의 현재 데스크톱 핸드오프에는 지도·권역 상세·검색 등이 포함되지만 월드컵 창과 타임라인 패널은 재작업 후 별도 전달 예정이라고 명시돼 있다. 현재 월드컵 API는 기존 계약으로 검증했으며, 최종 월드컵 화면의 필드·동작 일치는 새 시안을 받은 뒤 다시 확인한다. 시안의 예시 권역 수와 급지 전환 수, 실거래가 단순 순위, 같은 권역 대진 횟수는 현재 합의한 백엔드 정책을 바꾸는 근거로 사용하지 않았다. 적용 중인 정책은 [지도 탭 API](../architecture/map-tab-api.md)와 [월드컵 게임 API](../architecture/worldcup-game-api.md)에 기록했다.
