# 마장동 권역 추가와 단지 연결 (#91)

## 근거와 결정

- 사용자가 기준으로 확정한 `배치표(단가 포함)-update.pdf`의 3.7 행에는 `마장/이문`이 있다. 두 지역은 같은 초기 급지를 사용하지만 서로 떨어진 자치구에 있으므로 하나의 공간 권역으로 묶지 않는다.
- 기존 매핑은 162권역·254법정동이며 이문·휘경 3.7급은 포함했으나 성동구 마장동 `1120010500`은 빠져 있었다. 가장 가까운 행당 권역에 마장동 단지를 강제 배정하면 실제 경계와 급지가 어긋난다.
- `seongdong-majang`을 성동구 `11200`의 독립 권역으로 추가하고 초기 급지를 3.7로 정했다. 변경 후 매핑은 서울 133권역, 경기·인천 30권역, 총 163권역·255법정동이다. 기존 포일/내손은 한 권역으로 유지한다. 과거 노션의 서울 132권역·경기·인천 31권역안과 숫자는 같아도 구성은 다르다.
- #90은 권역 경계 변경을 제외하므로 이 변경을 별도 이슈 #91과 `feature/91-seongdong-majang-zone` 브랜치에서 처리한다. #90이 `develop`에 병합된 뒤 #91 브랜치에 최신 `develop`을 반영했으므로, 주소 보정과 지오코딩 코드를 기반으로 마장동 권역 변경을 추가한다.

## 경계 확보와 로컬 검증

- 2026-10-27 기존 VWorld 수집기 `scripts/location/download_boundaries.py`로 `LT_C_ADEMD_INFO`의 `emd_cd=11200105`를 요청했다. VWorld API 버전 2.0, 요청 좌표계 EPSG:4326을 사용했다. 응답의 `full_nm`은 `서울특별시 성동구 마장동`, 지오메트리는 `MultiPolygon`이다.
- 기존 254개 경계의 로컬 체크포인트를 재사용해 마장동 1개만 새로 수집했다. `data/location/boundary/legal-dong-boundaries.geojson`은 Git 제외 파일이다. 다른 환경에서는 본인 VWorld 설정을 준비하고 `python3 -B scripts/location/download_boundaries.py`로 255개 경계를 생성한다.
- 기존 수동 `LocationDataImportRunner`를 사용해 로컬 PostGIS에 적재했다. `zone`은 162개에서 163개로 늘었고 `seongdong-majang`의 `city_id=11200`, `tier=3.7`, 타입 `ST_MultiPolygon`, SRID 4326, `ST_IsValid=true`를 확인했다.
- #90에서 주소·법정동을 정정한 `A10020204` 마장한영스테이는 새 폴리곤 내부에 있었다. `scripts/location/assign_majang_complex.sql`로 로컬 DB의 `zone_id`를 채웠다. 스크립트는 법정동 코드, SRID, 공간 포함 관계, 기존 배정을 확인한 뒤 실행하므로 다른 환경에서는 #90의 주소 보정이 선행돼야 한다.

## 마장동 단지 수집

- 마장동 코드 `1120010500`으로 기존 단지 수동 적재기를 실행했다. 목록/기본정보 적재는 `SUCCESS`, 신규 9건, 실패 0건이었다. 실행 전 로컬 전체 단지는 4,307건, 실행 후 4,316건이다.
- 기존 마장한영스테이를 포함해 마장동 코드 단지는 10건이다. 신규 9건은 네이버 Geocoding과 PostGIS 판정을 거쳐 모두 `NEW_LOCATION_SAVED`·`MATCHED`로 `seongdong-majang`에 배정했다. 단지 목록에는 세대수 0건도 1개 있어 향후 300세대 투표 대상 기준과는 별도로 다룬다.
- 이번에 좌표·권역을 채운 신규 단지 ID는 `A10020365`, `A13305002`, `A13305003`, `A13305005`, `A13305006`, `A13305007`, `A13381601`, `A13381604`, `A13381608`이다. 로컬 DB의 마장동 코드 단지 10건 모두 위치가 있고 `zone_id=seongdong-majang`이다.
- 수동 수집 재개 기록 `data/complex/import-runs/majang.jsonl`은 Git에서 제외한다. 같은 매니페스트로 재실행하면 완료 법정동을 건너뛴다.

## 검증 및 남은 일

- `LocationMappingReaderTest`가 163권역·255법정동, 마장동 코드와 3.7급을 확인했다.
- `./gradlew clean build`가 성공했다. 지역·권역 적재를 다시 실행해도 권역은 163개, 전체 단지는 4,316개였다. 마장한영스테이 수동 배정 SQL도 재실행 시 `UPDATE 0`으로 종료됐다. 새 마장 권역과 기존 권역 사이에 면적이 겹치는 다각형은 0개이고, 마장한영스테이 좌표를 포함하는 권역은 마장 권역 하나뿐이다.
- 로컬 `.env`의 네이버 Maps 인증 정보로 신규 9건을 처리했다. 인증값과 API 응답 원문은 저장소나 문서에 기록하지 않는다. 로컬 DB는 권역 163개·단지 4,316개이며, 마장동 단지 10건 모두 SRID 4326이고 배정 권역의 폴리곤 내부에 있다. 각 좌표를 포함하는 권역은 정확히 1개였고 단지 ID 중복은 0건이었다.
- 신규 적재 표본 `A10020365`를 다시 실행하면 `ALREADY_ASSIGNED`로 건너뛴다. `./gradlew clean build`와 `git diff --check`가 통과했다. GitHub Actions CI는 PR을 만든 뒤 확인한다.
- #90은 `develop`과 `main`에 병합됐고, #91 브랜치에도 최신 `develop`을 반영했다. #91 작업 파일은 IntelliJ에서 여는 기본 저장소에 옮겨져 있으며, 로컬 DB의 마장동 권역과 단지 수집 결과는 그대로 유지된다.

## #90 단지 위치 예외의 #91 후속 검토

- 사용자 요청에 따라 #91 이슈 범위를 마장동 외 위치 예외 추적까지 넓혔다. 상세 내용과 12건별 보류 사유는 [단지 위치 예외 후속 검토](2026-10-27-complex-location-exception-followup.md)에 기록했다.
- 부산 `A10027875`는 수도권 수집 결과가 아니라 로컬 DB 저장 E2E 테스트가 남긴 행이었다. 연결 거래가 없고 예상 주소·법정동 코드와 일치함을 확인해 로컬 DB에서 제거했다. E2E 테스트에 트랜잭션 롤백을 추가했다.
- 마곡 7건은 승인된 단지별 배정 상태를 유지한다. 방화동 법정동 코드와 마곡 공간 경계의 충돌 원인은 아직 확정하지 않았다.
- 지번 재조회 후보 12건 중 11건은 VWorld 연속지적도의 해당 PNU 필지 안에 후보 점이 있고 기존 점은 밖에 있음을 확인했다. 법정동 코드와 대상 권역의 포함 조건까지 확인한 뒤 좌표·권역을 보정했다. 나머지 사당동 단지는 서울시 공개 단지 주소와 VWorld의 현행 사당동 1161 필지를 확인해 지번·좌표·권역을 별도로 보정했다. 하월곡·신대방 단지의 도로명주소 자치구 오기 2건도 서울시 공개 정보에 맞춰 정정했다.
- 최종 로컬 DB는 단지 4,315건, 좌표 4,315건, 권역 배정 4,315건이다. 마곡 7건의 원본 방화동 PNU는 현재 VWorld 지적도에서 조회되지 않았고 좌표 역조회는 모두 마곡동 필지였다. 현재 필지와 경계는 일치하지만 과거 필지 이력과 K-apt 원천 표기 이유는 미확인이다. 사당동 단지의 K-apt `42` 표기 경위도 미확인으로 기록했다.
