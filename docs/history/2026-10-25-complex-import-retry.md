# 공동주택 단지 수집의 부분 실패와 재시도 정책

## 배경

법정동 254개의 단지를 초기 적재하는 중 공공데이터 API가 HTTP 200으로 응답하면서 정상 `response` 대신 `OpenAPI_ServiceResponse`와 오류 코드 `04`를 반환했다. 같은 요청이 재실행에서는 성공하기도 했다. 첫 20개 법정동 시험은 단지 463건 중 신규 69건, 기존 18건, 실패 376건으로 중단했다. [공공데이터포털 오류 안내](https://www.data.go.kr/data/15058815/openapi.do)는 `04`를 HTTP 또는 제공기관 응답 처리 오류, `22`를 일일 호출 한도 초과로 구분한다.

## 결정

- 목록·기본정보 API의 정상 응답과 게이트웨이 오류 응답을 각각 파싱하고 결과 코드를 예외에 보관한다.
- 오류 코드 `04`는 최대 4회 호출한다. 실패 후 대기 시간은 2초, 4초, 8초다. 기본정보 API의 일시적인 연결·응답 오류도 같은 제한 안에서 재시도한다. 다른 결과 코드와 매핑 오류는 즉시 다시 호출하지 않는다.
- 목록 API의 최종 실패는 해당 법정동에 기록하고 다음 법정동을 처리한다. 기본정보 API의 최종 실패는 해당 단지에 기록하고 다음 단지를 처리한다.
- 코드 `22`가 나오면 호출 한도 소진으로 보고 현재 작업 전체를 중단한다. 나머지 법정동·단지를 계속 호출하지 않는다.
- 수동 실행은 설정한 법정동만 선택할 수 있다. 월간 예약 실행은 선택 설정과 관계없이 매핑의 전체 법정동을 처리한다. 예약 실행은 기본 비활성화한다.
- `app.complex-import.request-interval`로 같은 프로세스의 목록·기본정보 API 요청 시작 간격을 설정한다. 기본값 `0ms`는 추가 대기 없음이며, API `04` 직접 호출 실험에서 일정한 간격의 개선 효과를 확인하지 못했으므로 기본 대기 시간을 임의로 늘리지 않았다.
- `app.complex-import.schedule-cron`으로 예약 일정을 조정할 수 있다. 기본값은 매월 1일 02:00이고 시간대는 `Asia/Seoul`로 고정한다.
- 수동·예약 실행의 중복은 현재 애플리케이션 프로세스 안에서 막는다. 여러 프로세스 사이의 분산 잠금은 이 단계의 범위 밖이다.
- 외부 API의 오류 문구는 예외·적재 로그에 넣지 않는다. 결과 코드는 숫자 두 자리인 경우에만 보관하고, 그 밖의 값은 미확인 코드로 처리한다.

## 검증과 남은 문제

- 오류 코드 파싱, 백오프 횟수·간격, 한도 소진 시 중단, 수동·월간 코드 선택에 대한 테스트가 통과했다. `./gradlew clean build`도 성공했다.
- 실제 API에서 법정동 `1168010400`의 목록 조회는 한 실행에서 4회 모두 `04`로 실패했지만 재실행에서는 성공했고, 누락된 단지 1건을 저장했다. 다른 법정동 `1168010700`에서는 5건을 신규 저장했다.
- 2026-10-25 로컬 DB에는 단지 163건이 있다. 이 중 현재 권역 매핑에 속하는 것은 8개 법정동의 162건이다. 매핑 밖 법정동의 기존 1건은 이번 적재 결과로 계산하지 않는다.
- 로컬 DB 163건에서 단지명·지번주소 공백/누락, 법정동 코드 길이 오류, 세대수 음수/누락은 각각 0건이고 300세대 이상은 66건이다.
- 첫 5개 법정동 재실행에서 목록 API `04`가 모두 반복됐다. 짧은 직접 호출 간격 실험에서는 간격에 따른 일관된 개선을 확인하지 못했다. 따라서 전체 254개 법정동의 초기 적재와 실제 사용자 키의 남은 호출 한도는 아직 검증되지 않았다.

## 2026-10-26 재시도

- 어제 목록 API `04`로 실패했던 앞 5개 법정동은 모두 성공했고 기존 단지 84건을 건너뛰었다. 중복 저장은 없었다.
- 다음 10개 법정동을 한 번에 실행하다 180초 제한에 도달했다. 이때 단지 52건이 신규 저장됐다. 법정동 `1165010600`의 40건과 `1168010600`의 12건이며, 실행이 정상 완료되지 않아 두 법정동의 전체 수집 여부는 확인되지 않았다.
- `1168010600` 단독 재시도는 목록 API의 `04`가 4회 반복돼 실패했다. 다른 법정동 `1165010800`의 시험 요청도 `04`를 반환했다. 이 상태에서 추가 대량 호출을 멈췄다.
- 로컬 DB는 전체 215건·11개 법정동이며, 현재 권역 매핑 대상은 214건·10개 법정동이다. 단지명·지번주소·법정동 코드·세대수 필수 값 누락 및 음수 세대수는 0건이고 300세대 이상은 83건이다.
- 외부 API의 간헐적인 `04`와 사용자 키의 남은 호출 한도가 확인되지 않아, 254개 법정동 전체 초기 적재는 아직 완료되지 않았다.
- 원인을 좁히기 위해 요청 설정을 확인했다. 목록·기본정보 주소는 HTTPS의 `apis.data.go.kr` 서비스 경로이며 인증키에 URL 인코딩이 필요한 특수문자는 없다. 이전에 `04`를 반환했던 두 법정동의 목록 API와 기본정보 API를 같은 방식으로 3회씩 다시 호출했을 때 모두 `00`을 반환했다. 이어 실제 Java 배치로 `1168010600`을 재실행하자 목록 27건 중 기존 12건을 건너뛰고 15건을 신규 저장해 실패 0건으로 끝났다. 같은 코드·요청이 실패했다가 성공하므로 고정된 주소·파라미터·인증키 오류 가능성은 낮다.
- [공공데이터포털 오류 안내](https://www.data.go.kr/data/15057332/openapi.do)는 `04`를 허용되지 않은 HTTP 요청 또는 제공기관 API 응답 처리 실패로 설명한다. 관측 결과는 공공데이터포털 게이트웨이와 제공기관 사이의 간헐적인 처리 문제와 일치하지만, 어느 내부 구성요소가 원인인지는 외부 응답만으로 확정할 수 없다. 한도 초과 코드 `22`와 초당 한도 코드 `23`은 관측되지 않았다.
- 추가 저장 후 로컬 DB는 전체 230건·11개 법정동이고, 이 중 현재 매핑 대상은 229건·10개 법정동이다. 300세대 이상은 95건이다.
- 같은 날 법정동 `1165010800`을 별도로 실행해 단지 68건을 신규 저장하고 실패 0건으로 완료했다. 이어서 `1168011800`, `1168010100`은 각각 목록 API `04`로 실패했고, 다음 5개 법정동(`1168010300`, `1168010800`, `1165010100`, `1156011000`, `1117012900`)도 한 배치에서 모두 `04`로 실패했다. 배치는 실패한 법정동을 기록하고 다음 법정동을 처리했지만, 7개 연속 실패로 추가 호출을 중단했다.
- 그 시점의 로컬 DB는 전체 298건·12개 법정동, 현재 매핑 대상 297건·11개 법정동이다. 300세대 이상 115건이며 단지명·지번주소·법정동 코드·세대수 필수 값 이상은 0건이다. 254개 전체 적재는 여전히 미완료다.
