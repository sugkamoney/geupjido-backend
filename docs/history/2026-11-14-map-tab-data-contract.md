# 지도 탭 표시 데이터 기준 (2026-11-14)

관련 이슈: [#157](https://github.com/sugkamoney/geupjido-backend/issues/157)

## 배경

디자이너의 데스크톱 핸드오프는 `배치표 1.1`의 162개 권역, 배치표 원본값이 있는 133곳, 민심 전환 80표를 예시로 쓴다. 현재 서비스 DB는 서울·경기·인천의 승인된 서비스 권역과 추가 편집 급지를 관리하며, 투표 전환 조건은 유효표 50표·서로 다른 방문자 10명·권역 간 유효표 20표다. 화면에 시안 숫자를 그대로 고정하면 실제 DB 상태와 달라진다.

## 선택한 기준

- 지도 조회는 현재 서비스 DB에서 활성 지역의 권역과 단지를 읽는다. 시안의 권역 수·급지 수·표 수는 고정값으로 넣지 않는다.
- `initialTier`는 배치표 원본값과 추정 편집값이 섞인 **서비스 초기 급지**다. 배치표 1.1의 원본값이나 발행일로 표현하지 않는다. 별도의 원본 출처·날짜 컬럼이 없으므로 이를 추정해 응답하지 않는다.
- 초기·민심 급지 순위는 지도 화면에 보이는 일부 권역이 아니라 활성 서비스 권역 전체에서 계산한다. 민심 순위는 실제 투표 급지가 나온 권역만 대상으로 한다. 같은 숫자의 급지라도 원점수·표 수·이름·ID를 차례로 비교해 단일 순서를 부여한다. 초기 급지는 이름·ID로 최종 순서를 정한다.
- 권역 안 단지 목록은 현재 저장된 `zoneRank`를 따른다. 전환 전 잠정 순위는 대표 거래 총액이 아닌 ㎡당 가격이고, 전환 후에는 투표 점수다. 실거래가가 없거나 비활성 투표 후보인 단지도 지도 상세 목록에서 제거하지 않는다.
- 집계 상태는 마지막 발행 시점의 참여자·유효표와 현재 DB의 권역 수를 보여준다. 예약 실행이 꺼진 환경에서는 다음 반영 시각을 만들지 않는다.
- 핸드오프에 적힌 약 180m·310m 좌표 이동은 DB에 일괄 적용하지 않는다. 로컬 PostGIS에서 구·권역·단지 좌표의 SRID는 모두 4326이고, 권역 경계는 모두 유효하며, 좌표가 있는 단지는 모두 배정 권역의 경계 안에 있다. 지도 공급자와 실제 화면의 위치 차이가 확인되면 원천 좌표계와 표본을 대조해 별도로 보정한다.

## 화면 연동 영향

프런트엔드는 시안의 `배치표 1.1 기준`과 예시 날짜 대신 현재 데이터의 의미에 맞는 `초기 급지`를 표시해야 한다. 권역 급지 카드의 순위는 `initialRank` 또는 `voteRank`와 해당 전체 수를 사용한다. 단지 목록의 안내는 `rankingBasis=INITIAL`이면 `㎡당 대표 거래가 기준`, `VOTE`면 `투표 결과 기준`으로 나눈다. 지도 확대·선택·라벨 충돌 처리와 네이버 지도 SDK 연결은 프런트엔드 동작이다.
