# 단지 좌표·권역 수동 배치 처리 기준 (2026-10-27)

## 결정

- 이슈 #90의 단지 좌표·권역 적재는 기본적으로 비활성화한다. 단건 검증과 여러 건 처리는 각각 별도 설정으로 켜며 동시에 실행할 수 없다.
- 여러 건 처리는 한 번에 1~20개 단지 ID를 조회한다. `afterId`보다 큰 ID를 정렬해 조회하므로 실행 결과의 `nextAfterId`로 다음 구간을 이어서 처리할 수 있다.
- 좌표와 권역이 모두 있는 단지는 조회 대상에서 제외한다. 좌표만 있는 단지는 외부 지오코딩 API를 다시 호출하지 않고 권역만 재판정한다.
- 지오코딩 결과가 여러 건이면 자동 선택하지 않는다. 해당 단지 ID와 `MULTIPLE_GEOCODING_RESULTS`를 보류 목록에 남기고 다음 단지로 진행한다. 보류된 단지도 다음 시작 커서 이전에 있으므로 자동 재개 대상에서 빠진다.
- API 오류와 예상하지 못한 응답 오류는 즉시 전파해 배치를 중단한다. 시작·완료 로그의 단지 ID와 커서로 마지막 완료 위치를 확인한다.

## 현재 구현과 확인 범위

- `ComplexLocationBatchService`가 제한 건수 조회, 순차 처리, 다음 커서와 보류 목록 반환을 담당한다. `ComplexLocationBatchRunner`가 수동 실행 설정을 읽고 결과를 로그에 출력한다.
- 수동 배치는 시작 전에 결과 파일을 준비하고, 단지별 결과를 `data/complex/location-runs/local.jsonl`에 즉시 추가한다. 경로는 `COMPLEX_LOCATION_BATCH_MANIFEST_PATH`로 지정할 수 있다. 기본 경로는 Git에서 제외한다.
- 각 JSONL 행에는 기록 시각, 단지 ID, 처리 결과, 권역 판정, 후보 권역 ID, 다음 시작 커서만 담는다. 주소, 인증키, API 응답 원문과 예외 메시지는 기록하지 않는다. 복수 지오코딩 결과는 `MULTIPLE_GEOCODING_RESULTS`로 보류하고, 다른 오류로 중단되면 `ABORTED` 행에 실패한 단지 ID와 마지막 완료 커서를 남긴다.
- JSONL은 단지별 시도 이력이다. 재실행하면 같은 단지에 대한 행이 추가될 수 있으며 최종 상태를 집계할 때는 마지막 시도를 기준으로 확인해야 한다. 별도 DB 테이블은 만들지 않는다.
- 복수 결과 뒤 다음 단지 처리와 API 오류 중단은 단위 테스트로 확인했다.
- 월간 단지 마스터 수집 뒤 `ComplexLocationJobService`가 남은 단지를 20건씩 순회하도록 연결했다. `COMPLEX_LOCATION_SCHEDULE_ENABLED`는 기본적으로 꺼져 있고, 켤 때는 네이버 Geocoding도 활성화해야 한다. 실제 예약 시각 실행은 배포 환경에서 확인해야 한다.

## 사용자 확정 사항의 로컬 DB 반영

- 재실행 가능한 [`scripts/complex/apply_reviewed_locations.sql`](../../scripts/complex/apply_reviewed_locations.sql)을 단일 트랜잭션으로 실행했다. 단지 ID·기존 주소·법정동 코드·좌표와 대상 권역의 공간 포함 조건을 검사하며, 하나라도 다르면 전체를 롤백한다.
- `A10020204`: 지번주소를 `서울특별시 성동구 마장동 783-5 한영스테이`, 법정동 코드를 마장동 `1120010500`으로 수정했다. 사용자가 맞다고 확인한 도로명·기존 좌표를 유지했고, 마장동 권역이 없으므로 `zone_id`는 `NULL`이다.
- `A10027572`: 잘못된 고양시 도로명주소를 `서울특별시 마포구 월드컵로25길 26 마포영화블렌하임`으로 수정했다. 사용자 확인 지번의 네이버 단일 조회 좌표 `(126.9063069, 37.5584937)`와 `mapo-mangwon-hapjeong` 권역을 저장했다.
- 방화동 주소 7건: 원본 도로명·지번·법정동 코드는 그대로 두고, 각 점이 `gangseo-magok` 다각형 내부에 있으며 포함 후보가 1개임을 검사한 뒤 `zone_id`만 `gangseo-magok`으로 설정했다.
- 수정 후 로컬 DB 단지 4,307개 중 좌표 4,306개, 권역 배정 4,293개다. 좌표 없는 단지 1개, 좌표는 있으나 권역 없는 단지 13개다. 배정 좌표가 권역 폴리곤 밖인 건은 0개다. **법정동 코드와 배정 권역이 다른 7건은 모두 사용자 승인 마곡 예외**이며, 그 외 불일치는 0개다.

## 후속 확인

- 남은 12건의 지번주소 좌표 후보는 실제 단지 부지·출입구와 대조한 뒤 저장 좌표 교체·권역 배정 정책을 결정한다. 원본 도로명과 지번이 다른 시·구를 가리키는 2건은 원천 데이터 오류 여부도 확인한다.
- 마장동을 서비스 권역에 포함할지 결정한다. 현재 매핑에 없으므로 마장한영스테이의 `zone_id`는 비워 둔다. 부산 1건은 수도권 수집 범위에서 제외할지 검토한다.
- 마곡 7건의 단지별 예외는 일반 배정 규칙과 별도로 관리한다. 운영 DB 반영 시 같은 좌표·권역 검증을 다시 실행한다.
- 월간 연결은 코드와 테스트로 검증했다. 실제 예약 시각의 실행·API 이용량·작업 시간은 배포 환경에서 확인한다.
- 재실행할 때는 `ABORTED` 행의 `nextAfterId`부터 재개하고, 보류된 단지는 매니페스트의 ID를 사용해 별도로 재검토한다. 같은 매니페스트를 사용한 배치 두 개를 동시에 실행하지 않는다.
